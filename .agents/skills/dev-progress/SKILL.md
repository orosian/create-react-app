# 功能开发进展（PRD → 计划 → 开发 → 更新进展）

按用户指定的冲刺 PRD 做功能交付，并用同目录文档保持接力真相。真相源在文档树，不在聊天记录。

## 文档布局

用户会给出一个 PRD（或 Phase）路径。同级目录应包含：

```text
<功能目录>/
├── 总体规划.md          # 阶段路线、红线、当前冲刺指针
├── 进展.md              # 当前状态与下一刀（验收完成后更新）
└── <用户指定的 PRD>.md  # 本阶段唯一派工真相源
```

示例：`docs/产品文档/web集成/Web平台-Phase0.md` → 同级读 `总体规划.md`、更新 `进展.md`。

若缺少 `总体规划.md` 或 `进展.md`：先说明缺失，问用户是否按下方模板新建，**不要 silently 跳过**。

## 强制工作流

严格按顺序。跳过任一步都会造成错误派工或进展漂移。

### 1. 定位文档

1. 从用户消息取出**明确指定的 PRD 路径**。未指定则停下来问，不要猜「当前冲刺」。
2. 解析同级目录：`总体规划.md`、`进展.md`。
3. 先读 `总体规划.md`（边界、阶段表、红线、当前冲刺指针），再读指定 PRD（验收范围），再读现有 `进展.md`（已通 / 未通 / 下一刀）。

文档优先级：

| 问题                     | 信谁                                             |
| ------------------------ | ------------------------------------------------ |
| 本阶段做什么、验收什么   | 用户指定的 PRD                                   |
| 阶段顺序、红线、不做清单 | `总体规划.md`                                    |
| 现状与接力               | `进展.md`                                        |
| 愿景 / 远期设计          | 总体规划里链到的上游文档（只作背景，不直接派工） |

PRD 与总体规划冲突时：以 PRD 为冲刺范围，但**红线以总体规划为准**；冲突写进计划里让用户确认。

### 2. 先计划，再开发

在改任何业务代码之前：

1. 若环境支持计划模式（Cursor Plan Mode、Claude Code plan 等），先切入计划模式。
2. 产出简短实施计划，至少包含：
   - 范围：本 PRD 做 / 不做
   - 关键落点（包 / 模块 / API）
   - 红线（从总体规划摘录）
   - 验收方式（测试命令、手测路径）
   - 风险与开放决策
3. **等用户确认计划后**再实现。用户说「按计划做 / 可以 / 开工」才进入编码。

中途若发现计划与代码现实不符，先更新计划说明偏差，再继续——不要默默扩大范围。

### 3. 开发

- 只实现已确认计划内、且落在指定 PRD 验收范围内的内容。
- 跑 PRD / 计划里写明的验收（优先仓库既有 e2e / make 目标）。
- 不要为了「写进展」去改无关文件或补文档散文。

### 4. 验收完成后更新 `进展.md`

**仅当本阶段 / 本 PRD 验收完成**（测试通过且用户确认交付，或用户明确说「验收完成 / 更新进展」）时更新同级 `进展.md`。

开发中途、部分完成、仅出了计划：**不要**改 `进展.md`。

更新目标是反映**当前进展**，不是另写长篇验收摘要。优先改这些位置（文件已有章节则就地改；没有则只加最小必要块）：

1. **文首状态行**：阶段名、已交付 / 未开工、日期
2. **阶段总览表**：把本阶段状态改为已交付（或部分交付时写清前后端等子状态）
3. **下一刀 / 接力**：按总体规划指向下一未开工阶段；删掉已过时的「建议先做 X」
4. **一页备忘**（若有）：已通 / 未通 / 红线各一行内更新

刻意不做：

- 不要新增长篇「验收摘要」章节（API 全表、测试 ID 逐条复述）——细节留在 PRD
- 不要把聊天过程、失败尝试写进进展
- 不要改 `总体规划.md` 的路线愿景（除非用户明确要求同步状态列；默认可只改进展）
- 不要更新其他功能目录下的进展文档

若 `进展.md` 不存在且用户同意新建，用下方最小骨架，填入本阶段真实状态后写入。

## `进展.md` 最小骨架

新建时用此结构（标题换成功能名）：

```markdown
# <功能名> — 进展与接力指南

> **文档状态**：<当前阶段与状态>（YYYY-MM-DD） **适用范围**：接手本功能的工程师与 AI 代理 **冲刺真相源**：[`./<prd文件名>`](./<prd文件名>) > **总体规划**：[`./总体规划.md`](./总体规划.md)

---

## 1. 阶段总览

| 阶段        | 主题     | 状态                         |
| ----------- | -------- | ---------------------------- |
| **Phase-X** | <一句话> | **已交付** / 未开工 / 进行中 |

---

## 2. 下一刀建议（接力）

1. …

---

## 3. 一页备忘

- **已通**：…
- **未通**：…
- **红线**：…
- **真相源**：冲刺看 PRD；路线看 `总体规划.md`。
```

已有长文档（如含历史验收节）时：**保留历史章节**，只更新文首、总览表、下一刀、一页备忘，避免大删大改。

## `总体规划.md` 怎么用

开工前从中提取：

- 目标一句话与三方边界 / 红线
- 阶段路线图与「当前冲刺」指针
- 明确不进本阶段的项（飞书、RBAC、画布等）

开发过程中不要把总体规划里的远期项提前实现。计划里若用户想加范围，标成「超出本 PRD」，请用户改 PRD 或改计划。

## 触发后的最短检查清单

```text
[ ] 用户指定了 PRD 路径
[ ] 已读同级 总体规划.md + 进展.md + 该 PRD
[ ] 已出计划并得到用户确认
[ ] 实现范围 ⊆ PRD ∩ 计划
[ ] 验收通过（或用户确认交付）
[ ] 已更新同级 进展.md 的当前状态（非长摘要）
```

## 反例

| 错误                                    | 正确                      |
| --------------------------------------- | ------------------------- |
| 未指定 PRD 就按「感觉上的下一阶段」开干 | 先问清 PRD 路径           |
| 没出计划直接改代码                      | 先计划、确认后再写        |
| 写了一半就改进展为「已交付」            | 验收完成后再改            |
| 在进展里粘贴完整 API/测试矩阵           | 只更新状态与下一刀        |
| 把 Web 进展写进扩展点目录               | 只更新 PRD 同级 `进展.md` |
